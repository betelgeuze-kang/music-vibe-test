# 함께 듣기와 주간 기록 — JN1

기존 Draft PR #32의 홈·결과·테스트·오늘의 선곡 다음으로, 친구 초대와 비교, 주간 기록을 `DESIGN.md`의 종이색·초록색으로 연결한다. 운영 배포와 사용자 성과는 별도 확인 대상이다. 광고는 계속 비활성이다.

## 친구 초대와 비교

- 내 취향의 원본 레코드 그림, 친구의 빈 자리를 나란히 보여주고 링크 보내기 → 각자의 취향 만들기 → 다섯 곡 고르기로 안내한다. 긴 초대 URL과 익명 프로필 ID는 화면에 인쇄하지 않는다.
- 받은 초대는 친구의 취향을 먼저 보여준다. 테스트 중 새로고침하거나 중단·홈·이어하기를 거쳐도 초대가 fragment 안에 유지된다. 초대를 위한 저장소 키를 추가하지 않는다.
- 받은 링크를 붙여넣는 폼은 오류를 입력칸 아래에 남기고 초점을 유지한다. 정상 링크는 새로고침 후에도 같은 비교가 열린다. 다른 친구와 비교를 선택하면 현재 URL에서 compare/ref를 제거한다. 브라우저 뒤로 가기로 이전 초대 URL을 다시 방문하는 것은 가능하다.
- 공명도·발견 가능성은 사이트 내부 지표임을 펼쳐보기로 설명한다. 관계의 궁합이나 곡 선호 확률로 표현하지 않는다.
- 다섯 곡으로 이동하는 버튼은 목록 제목으로 스크롤하고 키보드 초점을 옮긴다. 공유 선곡도 곡 열기와 검색을 구분한다. 반응은 현재 사용자의 추천에만 반영하며 친구의 취향은 수정하지 않는다.
- 같이 듣기의 곡 클릭은 이전에 선택했던 개인 상황 대신 `together`로 기록한다. 링크를 받는 사람에게 취향 수치와 익명 식별자가 전달된다는 설명을 표시한다. 이름·연락처·개별 답변은 포함하지 않는다.

## 주간 기록

- 날짜 → 요약과 원본 레코드 그림 → 기록의 출처 → 저장된 날짜 → 장면과 곡으로 구성한다. 변화 수치와 태그는 기본적으로 접는다.
- 최소 세 개는 사이트의 분위기 선택·곡 링크 클릭·곡 반응을 합친 수이며, 세 종류를 모두 해야 하는 것은 아니다. 준비 전 화면에서 구체적으로 설명한다.
- 준비된 기록과 부족한 기록 모두 날짜를 선택할 수 있다. 날짜는 `#/weekly?week=YYYY-MM-DD`로 유지하며 실제 달력 날짜만 허용한다. 지난 기록을 고른 뒤 새로고침해도 같은 범위로 열린다.
- 외부 서비스의 재생 여부와 청취 시간을 가져오지 않는다는 점을 화면과 내보내는 카드에 명시한다. 기록이 세 곡보다 적으면 ‘세 곡’이라고 고정해서 표시하지 않는다.
- 1200×1500 주간 PNG도 같은 색상과 레코드 그림을 사용한다. 프로필 ID, 초대 토큰, 외부 이미지 요청은 포함하지 않는다. 실제 소셜 앱 게시 여부와 사이트 안의 이미지 생성은 별도다.

## 검증과 검토 범위

- 단위·릴리스: `npm run ci`. 윤년·잘못된 날짜, 8개 유형×2개 언어의 SVG 문구 보존과 식별자 제외, 직접 링크 표기와 친구 프로필 불변성을 검사한다.
- 추가 브라우저 흐름: `tests/e2e/journal-experience.spec.mjs`. 초대 후 새로고침·중단·이어하기, 링크 오류·붙여넣기, 피드백·초대 닫기, 클릭 상황, 날짜별 기록·새로고침, 대비와 접근성, 320/768/1280px 배치를 검사한다.
- 기존 GA4 동의·철회·fragment 회귀와 홈·결과·테스트·선곡·정적 콘텐츠 검사를 유지한다.
- `.refresh-journal`은 주간 기록·초대 화면의 데스크톱/모바일 네 장만 갱신한다. 다른 열두 장은 기존 승인 이미지와 비교한다. 갱신 실행과 최종 비교 실행은 구분한다.
- 화면 예시는 브라우저 테스트가 만든 합성 취향·기록이다. 모바일 프로젝트는 Chromium에서 iPhone 크기를 사용하며 실제 Safari나 OS 공유 시트를 검증한 것으로 보지 않는다.

이 문서는 구현 범위와 재현 방법이다. 현재 PR·정확한 커밋의 검사·병합·운영 배포 상태는 GitHub의 최신 상태와 별도 검토 기록으로 확인한다.
